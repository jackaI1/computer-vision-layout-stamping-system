# Working with editable drawings

I added this route so I can keep a drawing editable after stamping its sheets.
It runs alongside the original PDF app. It does not need AutoCAD to read DXF,
and does not start a web server.

## Try the generated floor plan

Use the Python environment from the README. The three files in `examples/cad/`
are generated by `python examples/make_sample_cad.py`. They contain only invented
rooms, furniture and a demonstration seal. To regenerate in another folder:

```sh
python examples/make_sample_cad.py --output-dir output/cad-input
python -m stamper.cad inspect output/cad-input/floor_plan.dxf
python -m stamper.cad stamp output/cad-input/floor_plan.dxf --seal output/cad-input/demo_seal.dxf --layout A101 --layout A102 --center 350 180 --diameter 40 --date 2026-11-04 --caption "DEMONSTRATION ONLY" -o output/cad/floor_plan_stamped.dxf --pdf output/cad/floor_plan_stamped.pdf
```

The PDF contains two A3 sheets, each 420 by 297 mm. The floor plan lives in
model space at full size; each sheet has a viewport, a window that shows a
scaled part of that plan. The seal lives in paper space, the sheet itself, so
its printed size stays the same across differently scaled views.

## Layer and reference controls

```sh
python -m stamper.cad edit examples/cad/floor_plan.dxf --off NOTES --bind-xrefs -o output/cad/no_notes.dxf
python -m stamper.cad edit output/cad/no_notes.dxf --on NOTES -o output/cad/notes_restored.dxf
python -m stamper.cad plot output/cad/notes_restored.dxf --layout A101 -o output/cad/a101.pdf
```

`inspect` prints JSON containing on/off, frozen, locked and plot states, sheet
bounds and top-level reference paths or resolution errors. Names of layers are
case-insensitive. Turning a layer on also thaws it. Layer locking and plot flags
are otherwise retained. An off parent INSERT layer hides its referenced content.
`--off` and `--on` can be repeated on edit, stamp and plot commands.

An xref is another drawing linked into the host. I resolve each link relative
to the drawing that owns it, including nested links and Windows-style path
separators. For moved projects, repeat `--xref-dir /path/to/folder` to supply
search folders. Exact host-relative matches take priority; ambiguous matches
in search folders fail instead of choosing the wrong file. Files must have
their actual case on case-sensitive systems.

Binding imports drawing objects and their resources into local blocks, retaining
the original insertion position, rotation, scale and reference base point. Names
are prefixed when needed to preserve host layers. Nested overlays, links that
should appear only in their immediate host, do not propagate. Top-level overlays
are included. Cycles, missing files, nesting over 32 drawings and references newer
than their host fail with an error. I use R2018 drawings for the example.

Host settings on named xref layers, including nested layer paths and per-viewport
overrides, are transferred to the bound names. Non-default overrides of shared
layers `0` or `Defpoints` are rejected because changing those shared layers would
also change host geometry; move that source content to a named layer first.

Stamp and plot always bind references in memory before export because the
renderer cannot display unbound references. `edit --bind-xrefs` saves that binding
without adding a seal. An edit without binding rewrites reference paths relative
to the new output folder. The source and referenced files remain untouched.
AutoCAD does not display linked DXF xrefs itself, so bind the sample first before
opening it there. Bound blocks are self-contained and work in DXF or DWG.

## My own seal and sheet positions

I supply a vector DXF/DWG with the seal objects in model space. The importer
copies the geometry, centres its bounding box and scales its longest dimension
to `--diameter`. For a circular seal that is its diameter. Required fonts must
be installed for consistent text. Unsupported entities and embedded raster assets
are outside this vector-seal route; the PDF workflow accepts PNG seals.

`--center X Y` and `--diameter D` use the sheet's paper units, millimetres or
inches. X grows right and Y grows up. The origin is the printable lower-left
corner plus the layout's plot-origin offset. `inspect` reports the complete
paper bounds, which can start at negative coordinates when margins are set.
I explicitly select each sheet with `--layout NAME`; I can repeat it for a set
of sheets using the same position. For different title blocks I run each sheet
with its own position into a new drawing copy.

The imported seal, optional date and caption form one block on `STAMPER_SEAL`.
The layer is turned on, thawed, unlocked and made printable when stamping. The
whole block must fit on the sheet, including the caption. Coordinates must be
finite and the diameter positive. Date and caption are single lines up to 80
characters. A second stamping pass replaces only inserts marked with this
tool's `STAMPER_CAD` ownership data in the selected sheets; unrelated blocks stay.
Unused block definitions remain available in the drawing and can be purged in CAD.

## Optional DWG setup

DWG uses [ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter),
a separate free download with its own licence, not a bundled project dependency.
I tested release 27.10 on macOS arm64. Download the matching installer from ODA.
On macOS, copy `ODAFileConverter.app` to `/Applications` or `~/Applications`;
the tool detects both. On Linux install the converter and `xvfb`, or extract the
official AppImage. On Windows install ODA in its standard location.
For another installation location, set the full executable path:

```sh
export ODA_FILE_CONVERTER="/absolute/path/to/ODAFileConverter"
python -m stamper.cad edit output/cad/floor_plan_stamped.dxf -o output/cad/floor_plan.dwg
python -m stamper.cad plot output/cad/floor_plan.dwg --layout A101 -o output/cad/from_dwg.pdf
TEST_ODA=1 python -m pytest tests/test_cad_cli.py::test_real_oda_dwg_roundtrip_and_stamp -q
```

The same edit, stamp and plot commands accept DXF or DWG input. An output ending
in `.dwg` invokes ODA to write AutoCAD 2018 format. Conversion uses a temporary
folder that is removed after the command. A missing converter produces an error
with no substitute or renamed file. ODA may briefly display a window on macOS.

## Plot design and limits

I use [ezdxf's xref importer](https://ezdxf.readthedocs.io/en/stable/xref.html)
for references and its [drawing frontend](https://ezdxf.readthedocs.io/en/stable/addons/drawing.html)
for sheets and model-space viewports. SVG, a vector graphics format, retains
fractional paper dimensions. I inline its styles before MuPDF converts it to a
vector PDF, so closed outlines stay outlines. Each selected layout becomes one
page with its full paper region and plot rotation, without fit-to-extents scaling.
Off, frozen and non-plot layers are excluded. The drawing copy keeps the CAD
objects and layout settings.

This is a 2D review plotter, not AutoCAD's print engine. Paper-space plot scale
must be 1:1 and paper units mm or inches. Perspective and non-top viewports are
rejected. CTB/STB pen tables, 3D solids, AutoCAD-specific objects, exact rich-text
formatting and external image/font packaging are not implemented. I review the
actual plot, fonts, line weights and seal position before use. The CAD route does
not test overlap with drawing content and applying a seal does not approve it.

## Checks

`python -m pytest -q` runs existing PDF/UI tests and CAD file, layer, reference,
seal, plotting and CLI tests. The ODA test runs when `TEST_ODA=1`; otherwise it is
explicitly skipped. CI also runs it in a separate Linux job using the official
ODA download with a checked SHA-256, and publishes the sample DXF/PDF outputs.
Tests reopen saved drawings, audit them, check PDF page dimensions and ink at
expected positions, and cover nested/missing/cyclic references and output safety.
